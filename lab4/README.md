### Результаты экспериментов

| N | 8x8, GFLOPS | 16x16, GFLOPS | 32x32, GFLOPS |
| :--- | :--- | :--- | :--- |
| 200 | 111.61 | 117.48 | 84.92 |
| 400 | 149.70 | 153.19 | 125.75 |
| 800 | 154.68 | 159.92 | 149.25 |
| 1200 | 154.68 | 160.14 | 146.03 |
| 1600 | 154.95 | 160.63 | 153.45 |
| 2000 | 169.58 | 160.58 | 148.82 |

**Лучший результат:** $N = 2000$, блок `8x8` — **169.58 GFLOPS** (при этом на большинстве размеров $N = 200 \dots 1600$ стабильно лидирует конфигурация `16x16` с показателем до **160.63 GFLOPS**).

- **График времени:** Демонстрирует кубический рост времени выполнения ядра CUDA при увеличении размерности матрицы $N$ для всех конфигураций сетки блоков (`8x8`, `16x16`, `32x32`).
- **График производительности:** Показывает зависимость вычислительной мощности (GFLOPS) от размера блока потоков. С ростом $N$ производительность выходит на плато (~160 GFLOPS для двойной точности FP64); конфигурация `16x16` обеспечивает наиболее стабильный баланс между загрузкой мультипроцессоров и расходом разделяемой памяти (`shared memory`), тогда как блоки `32x32` уступают из-за повышенных накладных расходов на синхронизацию и большой расход `shared memory`.
